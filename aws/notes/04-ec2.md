## Part 1: What is EC2

What is EC2?
> Elastic Compute Cloud - service providing secure, resizable virtual servers known as instances.

What is an EC2 instance?
> An instance is a virtual server running in the cloud.

Why is EC2 considered IaaS?
> AWS manages the physical hardware, hypervisor and networking. You manage the OS, patching, software, and configuration. That is what makes it Infrastructure as a Service.

## Part 2: AMIs

What is an AMI (Amazon Machine Image)?
> AWS supported and maintained image that provides a template that includes the OS, software, and configuration needed to launch an instance.

What is included in an AMI?
> OS image, launch permissions, block device mapping (which volumes to attach), and any pre-installed software/config

What is the difference between a public AMI, an AWS Marketplace AMI, and a custom AMI?
> Public AMIs are free, vendor-provided, or community-shared base images. AWS Marketplace AMIs are vendor-certified, often pre-configured, paid or free images. Custom AMIs are private images you create from your own configured instances.

Can you use an AMI from eu-west-1 in us-east-1?
> No, AMIs are regional resources, but you can copy an AMI to another region if needed

Why would you create a custom AMI?
> To customise it to a specific requirement such as faster boot times (software already installed instead of using user data), consistency across instances, and baking in security hardening.

## Part 3: Instance Types

What do the letters and numbers in instance types mean (e.g., t3.micro)?
> Names are based on instance family, generation, processor family, capabilities, and size. `t` refers to the instance series, in this case it is the Burstable performance. The `3` refers to the version. The `micro` refers to the instance size. 

What is a general purpose instance (t2, t3, m5)? When would you use one?
> General purpose means a balance of compute, memory, and networking. Good for web servers, code repos, dev environments

What is a compute-optimised instance (c5, c6i)? When would you use one?
> Workloads that need high CPU performance (eg. Batch processing, scientific modelling, high-performance web servers and machine learning inference)

What is a memory-optimised instance (r5, r6i)? When would you use one?
> Workloads that need to process large datasets in memory (e.g. in-memory databases (Redis, Memcached), real-time processing of large unstructured data, high-performance relational/in-memory databases (SAP HANA).)

What is a storage-optimised instance (i3, d2)? When would you use one?
> workloads that need very high read/write speed to local storage (e.g. data warehouses, distributed file systems (HDFS/Hadoop), and large relational or NoSQL databases that need fast sequential reads and writes.)

What is a burstable instance (t2, t3)?
> The baseline of CPU performance (e.g., 10% of a full core for a t3.micro). Most of the time that's all you need because your app is sitting there doing very little.

What are CPU credits? What happens when you run out?
> While you're under that baseline, you're earning CPU credits. Think of them like a battery charging. When something happens that needs more power - someone hits your app, you install a package, you run a script - the instance spends those credits to burst above the baseline temporarily. If you run out of credits, your instance gets capped at the baseline and everything feels slow. It won't crash, it just can't burst any more until credits build back up.

## Part 4: Key Pairs and SSH Access

What is a key pair?
> a pair: a public key (stored by AWS) and a private key (you download and keep). AWS doesn't keep a copy of your private key. You use this to SSH into your EC2 instance

How do you SSH into an EC2 instance?
> ssh -i /path/key-pair-name.pem instance-user-name@instance-public-dns-name

What is the default username for Amazon Linux? For Ubuntu?
> Amazon Linux is `ec2-user`, Ubuntu is `ubuntu`. Worth memorising these.

What happens if you lose your private key?
> You lose SSH access; there are workarounds such as using SSM Session manager, or stop the instance - detach the root volume, attach it to another instance, add a new public key, reattach.

What is EC2 Instance Connect?
> browser-based SSH connection through the AWS console that pushes a temporary SSH key to the instance metadata. It still uses SSH under the hood and still needs port 22 open.

What is SSM Session Manager? Why might you prefer it over SSH?
> SSM Session Manager lets you open a shell on your EC2 instance through AWS, without needing SSH at all. Why you'd prefer it over SSH:
> - No port 22. You don't need to open SSH in your security group at all. That's one less attack surface.
> - No key pairs to manage. No private keys to store, lose, or rotate. Authentication is handled through IAM — if you have the right IAM permissions, you can connect.
> - No public IP needed. You can connect to instances in private subnets without a bastion host or VPN.
> - Logging. Every session can be logged to S3 or CloudWatch, so you have an audit trail of who connected and what they did.
> The catch is your instance needs the SSM Agent installed (it comes pre-installed on Amazon Linux and Ubuntu AMIs) and an IAM role with the AmazonSSMManagedInstanceCore policy attached.

## Part 5: User Data

What is user data?
> A script (typically bash) that you pass to an EC2 instance at launch time to automate bootstrap tasks like installing software, pulling code, or starting services.

When does user data run?
> When the instance first launches

Give an example of what you would put in a user data script:
```bash
#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
```

Does user data run on every boot or only the first boot by default?
> Only first boot by default

## Part 6: Instance Metadata

What is the instance metadata service?
> A service that lets an EC2 instance query information about itself at runtime, without needing an API key or IAM credentials. It's accessible from only within the instance.

How do you access instance metadata from inside an EC2 instance?
> By making an HTTP request to the link-local address (e.g. `curl http://169.254.169.254/latest/meta-data/instance-id`)

What useful information can you get from instance metadata?
> Things like instance ID, AMI ID, instance type, public/private IP addresses, security groups, IAM role credentials, availability zone, and hostname.

What is the difference between IMDSv1 and IMDSv2?
>  IMDSv1 uses a simple GET request to the metadata endpoint (request/response). IMDSv2 is session-based - you first make a PUT request to get a session token, then include that token as a header in subsequent GET requests.

Why is IMDSv2 more secure?
> The token requirement protects against several attack vectors. Specifically, it mitigates SSRF (Server-Side Request Forgery) attacks because an attacker who tricks your application into making a GET request to the metadata endpoint won't have a valid session token. The token also has a configurable TTL and can't be forwarded via HTTP headers in the same way a simple GET can be exploited.

## Part 7: Instance Lifecycle

What are the instance states? (pending, running, stopping, stopped, terminated)
> Pending → Running → Stopping → Stopped → Terminated. There's also Shutting-down as the transitional state before Terminated. You only get billed during the Running state (and partially during Stopping if it's an EBS-backed instance preparing to stop).

What is the difference between stopping and terminating an instance?
> - Stopping is like powering off a machine - the instance shuts down but the resource still exists and you can start it again later. 
> - Terminating is permanent deletion - the instance is destroyed and can't be recovered. Note: only EBS-backed instances can be stopped. Instance store-backed instances can only be running or terminated.

What happens to data on the root EBS volume when you stop an instance?
> Nothing, the EBS volume stays attached.

What happens to data on the root EBS volume when you terminate an instance?
> By default the root EBS volume is deleted when the instance is terminated, but this can be changed by setting the DeleteOnTermination flag to false.

What is termination protection?
> A safeguard you can enable that prevents an instance from being accidentally terminated. When enabled, any API call or console action to terminate the instance will fail until you explicitly disable the protection first.

What is EC2 hibernate?
>  Instead of a full shutdown, hibernate saves the contents of the instance's RAM to the root EBS volume, then stops the instance

## Part 8: Elastic IPs

What is an Elastic IP?
> EC2 instance's public IP is not permanent. Which is where Elastic IP comes in, this provides a static IP, which you can attach to an instance.

When does AWS charge for an Elastic IP?
> When you have an allocated IP, but it is not in use.

What is the limit on Elastic IPs per Region?
> 5

Why should you use DNS or load balancers instead of Elastic IPs in production?
> Elastic IPs are a fixed, limited resource and they tie you to a single instance, which doesn't scale. Load balancers distribute traffic across multiple instances, give you health checks, and handle failover automatically. DNS (like Route 53) gives you flexibility to route infrastructure without clients needing to know. Essentially, Elastic IPs are fine for dev/test or a single small server, but in production you want the scalability, redundancy, and flexibility that ALBs and DNS provide.

## Part 9: Instance Store vs EBS

What is an instance store?
> Provides temporary, high performance, block-level storage physically attached to the host computer of an EC2 Instance.

What happens to instance store data when the instance stops or terminates?
> Ephemeral data - data is not persistent and is lost when instance is stopped.

When would you use an instance store instead of EBS?
> Ideal for temporary, rapid changing data like caches, databases, scratch files, and buffer storage

What is the key difference between instance store and EBS?
> Unlike EBS volumes, which are network attached and persistent. Instance store is local and ephemeral.

## Part 10: Pricing Models

What is On-Demand pricing?
> Flexible, pay-as-you-go model for cloud resources (like EC2 instances or RDS database) that require no long-term commitments or upfront payments.

What are Reserved Instances? What commitment do they require?
> A billing discount model offering up to 72% savings over on-demand rates for committed 1 or 3 year usage.

What are Savings Plans? How do they differ from Reserved Instances?
> Saving plans automatically apply discounts across regions and instance families, providing greater flexibility. 

What is Spot pricing? What is the risk?
> Pricing fluctuation based on supply and demand. AWS can terminate instances with a 2-minute warning if they need the capacity back.

What happens when AWS reclaims a Spot Instance?
> After 2 minutes the instance will either be stopped, terminated or hibernated (if configured).

What are Dedicated Hosts? When would you need one?
> Normally EC2 instances run on shared physical hardware with other AWS customers. With a dedicated Host, the entire physical machine is yours.

When would you use each pricing model?
> **On-Demand** - Short-term, unpredictable workloads or development/testing. You pay per hour/second, no commitment. Example: Spinning up an instance to debug something for 2 hours.
> **Reserved Instances (1-year or 3-year)** - Steady-state production workloads where you know you'll need the same capacity for months/years. Example: A production web server that runs 24/7. Savings: Up to 72% vs On-Demand.
> **Spot Instances** - Fault-tolerant, flexible workloads that can tolerate interruption. Up to 90% cheaper but AWS can terminate with 2-minute notice. Example: Batch processing, data analysis, CI/CD runners (with checkpointing).
> **Savings Plans** - Commitment-based savings but more flexibility than Reserved Instances (can move between instance types/regions/OSes). Commit to a $/hr spend for 1-3 years to get 25-72% savings.
> **Dedicated Hosts** - Per-socket/per-core licensing requirements (e.g. Windows Server, Oracle DB) or regulatory/compliance needs requiring dedicated hardware.

## Part 11: Placement Groups

What is a placement group?
> A way to group EC2 instances together to control how they're physically placed on AWS hardware.

What is a Cluster placement group? When would you use it?
> Instances packed close together for ultra-low latency. Use for HPC, real-time data processing, or tightly-coupled distributed systems.

What is a Spread placement group? When would you use it?
> Instances spread across different hardware (max 7 instances per AZ per spread group) for maximum independence. Use for a small number of critical instances that can't fail together.

What is a Partition placement group?
> Instances divided into separate partitions on different hardware. Use for large distributed systems (Kafka, Hadoop) where you want to isolate failures by partition.

## Part 12: Elastic Network Interfaces (ENI)

What is an Elastic Network Interface (ENI)?
> A virtual network interface card that you attach to an EC2 instance to enable network communication.

What does an ENI contain? (private IP, MAC address, security groups, etc.)
> A primary private IP, optional secondary private IPs, a MAC address, security groups, and optionally an Elastic IP and network tags.

Can you attach multiple ENIs to a single instance?
> Yes, depending on instance type (e.g., t3.micro allows 2, t3.medium allows 3). Each ENI gets its own private IP and security group.

Can you move an ENI from one instance to another? Why is this useful?
> Yes, you can detach an ENI and attach it to another instance. Useful for failover—move a network interface (with its private IP and MAC address) to a standby instance to quickly restore service without reconfiguring DNS.

How is an ENI different from an Elastic IP?
> An ENI is the actual network interface; an Elastic IP is a static public IP address that you associate with an ENI. You can move an Elastic IP between ENIs, but the ENI is the underlying network card.

In what scenario would you use a secondary ENI?
> When you need multiple network interfaces on one instance—e.g., a dual-homed instance for both public traffic (on one ENI) and private backend traffic (on another ENI), or for high-availability failover where you swap ENIs between instances.

## Commands to Learn

```bash
# Show running instances
aws ec2 describe-instances --filters "Name=instance-state-name,Values=running"
```
> 

```bash
# create instance (Launch a new t3.micro instance with specified AMI, key pair, and security group.)
aws ec2 run-instances --image-id ami-xxxxx --instance-type t3.micro \
  --key-name my-key --security-group-ids sg-xxxxx
```
> 

```bash
# Stop instance
aws ec2 stop-instances --instance-ids i-xxxxx
```
> 

```bash
# start instance
aws ec2 start-instances --instance-ids i-xxxxx
```
> 

```bash
# terminate instance
aws ec2 terminate-instances --instance-ids i-xxxxx
```
> 

```bash
# create an AMI from the specified instance.
aws ec2 create-image --instance-id i-xxxxx --name "my-custom-ami"
```
>

aws ec2 describe-images --owners amazon \
  --filters "Name=name,Values=al2023-ami-*"
